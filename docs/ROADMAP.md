# Дорожная карта переноса PISMO на Linux

Цель — полный паритет функций с Windows-версией **без урезки**. Ниже — что уже
сделано, что осталось, и как именно каждая Windows-зависимость заменяется на Linux.

## Принцип

Windows-версия завязана на 4 подсистемы, которых нет на Linux:

| Подсистема | Windows | Замена на Linux | Статус |
|---|---|---|---|
| UI | WinForms | **Avalonia UI** (тот же C#, кроссплатформенно) | ✅ готово |
| Транспорт звонка | WebRTC (DataChannel) | **SIPSorcery** (чистый C#) — уже был в Windows-версии (`CallTransport.cs`) | ✅ перенесён |
| Аудио звонка | **NAudio** | **ALSA** (`arecord`/`aplay`) через `IAudioDevice` | ✅ голос готов |
| Видео/экран в звонке | WebView2 video-track | SIPSorcery media + V4L2/FFmpeg | 🚧 этап видео |
| Камера (кружки) | **AForge.Video.DirectShow** | **V4L2** (Linux) / FFmpeg | 🚧 |

> Примечание: изначально планировался CEF (как хост браузерного WebRTC), но
> оказалось, что аудиозвонок в Windows-версии идёт **не** через медиа-треки
> WebView2, а бинарными PCM-кадрами по **DataChannel** поверх SIPSorcery
> (`CallTransport.cs`). Значит браузер не нужен вовсе: SIPSorcery — чистый C#,
> ставится из NuGet, кроссплатформенный. Это и надёжнее, и легче CEF.

Кроссплатформенное переиспользуется как есть: **MySql.Data**, **SIPSorcery**,
`DBHelper`, `UserSession`, `TurnSettings`, вся SQL-логика.

- [x] Кроссплатформенный солюшн (`PISMO.Core` + `PISMO.Desktop` на Avalonia)
- [x] Перенос ядра: `DBHelper`, `UserSession`, `TurnSettings`
- [x] Сервисы данных: `AuthService`, `MessageService` (SQL 1:1 из `MainForm`)
- [x] UI: вход, регистрация, смена пароля, главное окно (диалоги + переписка), настройки
- [x] Личные сообщения: текст + изображения, поллинг, непрочитанные, admin-режим
- [x] Интерфейсы платформенных сервисов (`ICallEngine`, `IAudioDevice`, `ICameraDevice`)
- [x] Сборка и запуск проверены на Linux (.NET 8 + Avalonia 11, X11/Wayland)

## Этап 1 — Голосовые звонки ✅ (готово)

- [x] Перенос `CallTransport` (SIPSorcery, DataChannel) → `PISMO.Core/Call`
- [x] Сигналинг через БД `call_sessions` (`CallSignaling`): offer/answer/ICE,
      статусы, детект входящих — протокол 1:1 с Windows-версией
- [x] Схема БД звонков — `db/pismo_calls_migration.sql`
- [x] Аудио на Linux — `AlsaAudioDevice` (ALSA `arecord`/`aplay`, PCM 16кГц/моно)
- [x] `Views/CallWindow` — исходящий/входящий звонок, mute, завершение
- [x] `Views/IncomingCallWindow` — приём/отклонение
- [x] Кнопки 📞/📹 в чате и опрос входящих звонков в `MainWindow`
- [x] STUN в ICE-конфиге; TURN добавляется только если он включён и задан
      адрес. TURN-сервера у проекта нет, и раньше relay прописывался всегда —
      каждый звонок ждал ответа от машины, где на 3478 никто не слушает.

**Нужно проверить на реальных устройствах** (в этом окружении нет 2 пиров и
микрофона): установить `alsa-utils`, выполнить обе миграции БД, запустить на двух
машинах и позвонить. Формат аудио и сигналинг совместимы с Windows-клиентами.

## Этап видео — камера/экран/плитка ✅ (Linux ↔ Linux)

- [x] Захват камеры (v4l2) и экрана (x11grab) через `ffmpeg` → MJPEG → JPEG-кадры
      (`FfmpegVideoSource`), кадр ужат под лимит одного пакета DataChannel
- [x] Передача видео/экрана типами `TypeVideo`/`TypeScreen` по тому же транспорту,
      что и голос — видео физически не влияет на аудио
- [x] «Плитка» тайлов в `CallWindow`: своя камера, камера и экран собеседника;
      декод JPEG → Avalonia Bitmap
- [x] Кнопки камеры/экрана, изоляция ошибок (нет камеры/ffmpeg → откат на голос)
- [x] Захват (ffmpeg→MJPEG→кадры) проверен на реальном X-дисплее (валидные JPEG)

Осталось для видео:
- Совместимость видео с **текущим Windows-клиентом** (там видео на настоящих
  WebRTC-медиа-треках WebView2, а не JPEG-по-DataChannel). Варианты: добавить
  media-track путь на SIPSorcery, либо обновить Windows-клиент на приём кадров.
- Wayland без XWayland — нативный захват через PipeWire.
- Чанкинг кадров > 60 КБ (сейчас держим размер малым качеством/масштабом).

## Этап 2 — Голосовые сообщения и видео-кружки ✅

- [x] `Media/Wav.cs` — заголовок WAV своими руками (44 байта по неизменной
      спецификации). Нужен затем, чтобы голосовые с Linux читались
      Windows-клиентом: там их пишет NAudio, и в базе лежит обычный WAV —
      16 кГц, моно, 16 бит. ALSA даёт ровно такой PCM.
- [x] `Media/VoiceNote.cs` — запись через `arecord`, воспроизведение через
      `aplay`. Пишем СЫРОЙ поток и сами надеваем заголовок: у arecord есть
      режим записи сразу в WAV, но длину он дописывает при нормальном
      завершении, а останавливаем мы его убийством процесса.
- [x] `Media/VideoCircleCodec.cs` — контейнер PSMOVID1 байт в байт как на
      ПК. Отличие одно: Windows жмёт кадры из System.Drawing, а здесь JPEG
      уже готовые — их даёт ffmpeg, и лишнего перекодирования не происходит.
- [x] `Media/CircleRecorder.cs` + окна записи и просмотра: круглое превью,
      счётчик, предел в минуту (кружок целиком лежит в одной строке
      таблицы). Звук и картинка пишутся двумя независимыми процессами —
      для нескольких секунд расхождение незаметно, а мультиплексор дал бы
      формат, который Windows-клиент не прочитает.
- [x] Голосовые и кружки в переписке — кнопкой: байты тянутся по нажатию,
      как и файлы.
- [x] Нет `arecord`/`aplay`/`ffmpeg` — сказано, чего именно не хватает и
      какой командой ставится, а не «не удалось».

## Этап 3 — Расширенные сообщения ✅ / Группы 🚧

Личная переписка:
- [x] Ответы (`reply_to_id`): цитата над сообщением и полоска ввода «на что
      отвечаем». Цитата подтягивается join'ом на ту же таблицу — без
      отдельного запроса на каждое сообщение.
- [x] Правка (`edited_at`) и удаление (`is_deleted`). Удалённое остаётся
      следом «сообщение удалено», а не исчезает: иначе ответы на него
      начинают ссылаться в пустоту.
- [x] Файлы (`file_data`/`file_name`) — отправка любого файла, не только
      картинки, и сохранение по нажатию. Тяжёлые колонки при чтении
      переписки НЕ выбираются: берём только `LENGTH()`, байты тянем, когда
      нажали. Предел вложения 16 МБ объясняется сразу, а не отказом базы.
- [x] Закреплённые сообщения (`PinsRepository`) — отметка на пузыре,
      переключение из меню, отпечаток по открытому чату.
- [x] Меню сообщения: ответить, копировать, закрепить, изменить, удалить.
      Править и удалять можно только своё — условие стоит в самом UPDATE,
      а не только в меню.
- [x] Галочки прочтения (✓ / ✓✓) и событие `read` по сокету.

Группы:
- [x] Раздел «ГРУППЫ» в списке чатов, создание группы с выбором участников,
      окно состава (добавить/убрать). Создателя убрать нельзя: группа без
      него не видна даже ему самому — список строится по `group_members`.
- [x] Вся переписка группы работает теми же средствами, что личная:
      ответы, правка, удаление, файлы, закрепы (scope 1).
- [x] «Новое» в группе определяется по максимальному id — прочтений у
      групп нет и на ПК: в `group_messages` нет колонки `is_read`.
      Поэтому точка, а не число: число было бы взято с потолка.
- [x] Опрос групп отдельным дешёвым запросом — счётчик личной переписки
      о другой таблице ничего не знает.
- Звонки в группах.

- [x] Реакции (`ReactionsService`) — пилюлями под сообщением и подменю в
      меню сообщения. Эмодзи сравниваются ПОБАЙТОВО (`COLLATE utf8mb4_bin`):
      в обычных _ci-коллациях MySQL разные эмодзи считаются равными
      строками, и тумблер снимал бы чужую реакцию вместо своей.
- [x] Приватность ЛС (`user_prefs.dm_privacy`) — в `FriendsService`.

Осталось:
- Пересылка, упоминания, поиск по переписке.
- Блокировки (`user_blocks`).

## Серверы ✅ / голос в каналах 🚧

- [x] `PISMO.Core/Data/ServerService.cs` — весь SQL: серверы, каналы,
      участники, роли, баны, сообщения каналов, присутствие в голосовых.
      Права проверяются в САМИХ запросах: спрятанная кнопка — удобство, а
      не защита, у каждого клиента прямой доступ к базе.
- [x] `Views/ServersWindow` — четыре колонки, как на ПК: серверы, каналы,
      переписка, участники. Отдельное окно и НЕ модальное: из него хочется
      переключаться в личные сообщения и обратно.
- [x] Создание сервера и вход по номеру одним полем: число — вход,
      остальное — название нового.
- [x] Создание и удаление каналов, исключение и бан участников — по праву,
      которое подтверждает база.
- [x] Переписка каналов теми же средствами: ответы, правка, удаление,
      файлы. Чужое сообщение удаляет модератор — условие в самом UPDATE.
- [x] Присутствие в голосовом канале: видно, кто «в эфире», запись живёт,
      пока её обновляют (приложение могли закрыть крестиком — выйти за него
      будет некому).
- Сам голос в каналах серверов. Транспорт звонка на Linux (`CallTransport`,
  DataChannel) рассчитан на пару собеседников, а канал — комната на
  многих. Нужен либо SFU (как LiveKit на ПК), либо mesh на N участников.
  Личные и групповые звонки при этом работают.

## Сигналинг и присутствие ✅

- [x] `PISMO.Core/Net/SignalingClient.cs` — клиент ws-сервера, порт
      `WebSocketSignalingClient.cs`. До него Linux-клиент знал один способ
      узнать о новостях: спросить базу по кругу. Теперь новое сообщение,
      прочтение, звонок и смена статуса приходят сразу. Сервер
      необязателен: нет его — работает опрос, как раньше.
- [x] `JwtAuth` + `AppConfig` — та же подпись регистрации, что у ПК и
      телефона; секрет из env `PISMO_JWT_SECRET` или `pismo.config`
      (на Linux — рядом с программой либо в `~/.config/pismo/`).
- [x] `PISMO.Core/Data/PresenceService.cs` — в сети / бездействует / не в
      сети: те же пороги (40 и 90 секунд) и тот же расчёт, что на ПК.
      Активностью считается «окно программы активно» — как на Android;
      системного простоя ввода на Linux одинакового способа нет
      (XScreenSaver есть не везде и не работает на Wayland).
- [x] Кружок статуса на аватарке в списке и подпись под именем в шапке
      чата; статус рассылается по сокету при изменении и применяется
      мгновенно, снимок из базы его не затирает.
- [x] Список чатов держит положение ползунка при обновлении.

## Шифрование сообщений ✅

- [x] `PISMO.Core/Crypto.cs` — перенесён дословно из Windows-версии:
      AES-256-GCM (`enc:v2:`) на запись, чтение ещё и старого `enc:v1:`
      (AES-CBC). Ключ общий с ПК и Android — иначе клиенты не читают
      переписку друг друга.
- [x] `MessageService`: шифруем на отправке, расшифровываем в переписке и в
      превью списка диалогов.

## Друзья и профили ✅

- [x] `FriendsService` — заявки, принятие, удаление, поиск людей,
      приватность ЛС (`user_prefs.dm_privacy`). Колонки `friends.status`
      может не быть, если миграция на этой базе не выполнялась: тогда сам
      факт строки считается дружбой, а запросы строятся без неё — падать
      из-за неприменённой миграции клиент не должен.
- [x] `Views/FriendsWindow` — вкладки «В сети», «Все», «Ожидание»,
      «Найти»; отношение ко всему списку подтягивается одним запросом, а
      не по одному на строку.
- [x] `ProfileService` + `Views/ProfileDialog` — баннер, аватар, «о себе»,
      ссылки. Свой профиль правится на месте, чужой только смотрится.
      Картинки читаются ОТДЕЛЬНО от текста и уже после показа окна: аватар
      нужен в списке на каждой строке, баннер — только в открытом профиле.
- [x] Профиль открывается правой кнопкой по собеседнику (у админа правая
      кнопка занята входом за пользователя) и по строке в списке друзей.

## Этап 4 — Полировка 🚧

- [x] Значок в трее (`TrayIcon`) и уведомления рабочего стола через
      `notify-send`. Своей всплывашки не рисуем: системный демон уже знает
      и про «не беспокоить», и про историю, и про полноэкранные программы.
      Уведомление показывается, только когда окно не на виду.
- [x] Крестик спрашивает один раз: свернуться в значок или выйти. Молча
      прятать нельзя — значок на Linux показывает окружение, и не во всех
      он есть; спрятать окно в несуществующий значок значит потерять
      программу.
- [x] CI-сборка на каждый пуш (`.github/workflows/build.yml`) и выпуск
      релиза кнопкой (`release.yml`): самодостаточный архив со средой .NET
      внутри, ставить её отдельно не нужно.
- [x] Автообновление (`PISMO.Core/Updater.cs`): при запуске тихо спрашивает
      GitHub про свежий релиз, предлагает обновиться, скачивает `tar.gz` и
      перезапускается. Установку из пакета не трогает.
- Упаковка в AppImage / Flatpak / `.deb` — архива хватает для запуска,
  но не даёт значка в меню.
- Сборка под Windows/macOS из того же кода.

## Проверка сборки

```bash
dotnet build            # весь солюшн
dotnet run --project src/PISMO.Desktop
```

Заметки по окружению для разработки без физического дисплея (headless-проверка):

```bash
xvfb-run -a dotnet run --project src/PISMO.Desktop
```
